# REST API Contracts

> REST API contracts between the Enforce Script game mod and the Python FastAPI bridge.
> All communication occurs over HTTP on `127.0.0.1:5001`.

---

## Transport Overview

| Property | Value |
|---|---|
| Protocol | HTTP (plaintext, localhost only) |
| Host | `127.0.0.1` |
| Port | `5001` |
| Content-Type | `application/json` |
| Direction model | Game initiates all requests (POST SITREP, GET orders). Bridge never calls the game directly. |
| Async model | Enforce Script REST is callback-based (`RestCallback`). Bridge is async (FastAPI + uvicorn). |

### Port configuration consistency

| Component | File | Port |
|---|---|---|
| Bridge config | `python_bridge/config.json` | 5001 |
| Bridge launcher | `start_bridge.bat` | 5001 |
| Game mod default | `LLMBridge.c` (hardcoded default) | 5001 |
| Enforce Script examples | Various `GetContext("http://127.0.0.1:5001")` | 5001 |

> If the port changes, ALL three locations must be updated simultaneously.

context for LLM prompts.

```json
            "current_waypoint": [5500.0, 0.0, 7000.0],

        {
            "squad_id": "OPFOR_SQUAD_3",
            "leader": "AI",

        {

```

**Response:**

```json
{

    "received_at": "2026-08-08T21:26:00.123Z"

```

**Enforce Script caller:**

```c
RestContext ctx = GetGame().GetRestApi().GetContext("http://127.0.0.1:5001");
LLMBridgeCallback cb = new LLMBridgeCallback("SITREP");
ctx.POST(cb, "/sitrep", sitrepJsonString);
```

**Python bridge handler:**

```python
@app.post("/sitrep")
async def sitrep(request: SitrepRequest):
    world_state.update(request.dict())
    return {"status": "ack", "received_at": datetime.utcnow().isoformat()}
```

### POST /command/result

Feedback on command execution. The game reports whether a command succeeded or failed.

**Request body:**

```json
{
    "command_id": "CMD-2026-0808-001",
    "status": "SUCCESS",
    "result": {
        "action": "MOVE",
        "squad_id": "BLUFOR_SQUAD_1",
        "position": [5500.0, 0.0, 7000.0],
        "arrived": true,
        "casualties": 0
    }
}
```

**Status values:** `SUCCESS`, `PARTIAL`, `FAILED`, `CANCELLED`

**Response:**

```json
{
    "status": "ack"
}
```

## Endpoints: Bridge → Game (via polling)

### GET /orders

The game polls this endpoint to retrieve pending commands. Commands are generated by
the LLM and queued by the bridge.

**Response body (JSON array):**

```json
[
    {
        "command_id": "CMD-2026-0808-001",
        "squad_id": "BLUFOR_SQUAD_1",
        "action": "MOVE",
        "position": [5500.0, 0.0, 7000.0],
        "params": {
            "formation": "WEDGE",
            "stance": "CROUCH",
            "combat_mode": "HOLD_FIRE",
            "completion_radius": 15.0,
            "replace_existing": true
        }
    },
    {
        "command_id": "CMD-2026-0808-002",
        "squad_id": "OPFOR_SQUAD_3",
        "action": "ATTACK",
        "position": [4500.0, 0.0, 5000.0],
        "params": {
            "formation": "LINE",
            "stance": "PRONE",
            "combat_mode": "OPEN_FIRE"
        }
    }
]
```

**Command action types:**

| Action | Description |
|---|---|
| `MOVE` | Move to position |
| `ATTACK` | Move to position and engage enemies |
| `DEFEND` | Hold position and defend |
| `HOLD` | Stop and hold current position |
| `FORMATION` | Change formation only |
| `STANCE` | Change stance only |

**Enforce Script caller (polling loop):**

```c
// In LLMBridge.Update() (called via CallLater every 2s):
RestContext ctx = GetGame().GetRestApi().GetContext("http://127.0.0.1:5001");
LLMBridgeCallback cb = new LLMBridgeCallback("POLL_ORDERS");
ctx.GET(cb, "/orders");

// In RestCallback.OnSuccess:
// Parse JSON array → for each command → execute via SCR_AIGroup
```

```json
    "status": "queued",
```

> directly by an external tool for development/testing.

## Known Gaps (F1.3 — Route Sync)

### Gap 1: /waypoint endpoint mismatch

- **Game mod** (`LLMBridge.c`): Has `POST /waypoint`
- **Bridge** (`main.py`): Does NOT have `/waypoint`
- **Fix**: Either add `POST /waypoint` to `main.py` or remove the call from `LLMBridge.c`
  and use `GET /orders` polling instead.
- **Recommendation**: Remove from `LLMBridge.c`. The polling model (GET /orders) is cleaner
  and more resilient — the game can poll at its own pace without blocking.

### Gap 2: /status method mismatch

- **Game mod** (`LLMBridge.c`): Sends `POST /status`
- **Bridge** (`main.py`): Expects `GET /status`
- **Fix**: Change `LLMBridge.c` to use `ctx.GET(cb, "/status")` instead of `ctx.POST(cb, "/status", "")`.
- **Root cause**: Status is a read-only health check, so GET is semantically correct.

### Resolution checklist (F1.3)

1. [ ] Remove `POST /waypoint` from `LLMBridge.c` (or add handler in `main.py`)
2. [ ] Change `/status` call in `LLMBridge.c` from POST to GET
3. [ ] Verify both sides agree on JSON schema for SITREP and orders
4. [ ] Add Pydantic models in `main.py` matching the SITREP and command formats
5. [ ] Test e2e: bridge running + game launched → SITREP received → order returned → executed

## JSON Schema Definitions

### SITREP schema (Pydantic)

```python
from pydantic import BaseModel
from typing import List, Optional
from datetime import datetime

class SquadState(BaseModel):
    squad_id: str
    leader: str
    leader_rank: Optional[str] = None
    members: int
    position: List[float]  # [x, y, z]
    current_waypoint: Optional[List[float]] = None
    status: str
    faction: str

class Objective(BaseModel):
    id: str
    type: str  # SEIZE, DEFEND, REINFORCE
    position: List[float]
    status: str
    controlling_faction: str

class AICount(BaseModel):
    US: int
    USSR: int
    total: int
    limit: int

class Casualties(BaseModel):
    US: int = 0
    USSR: int = 0

class SitrepRequest(BaseModel):
    timestamp: str
    faction: str
    squad_states: List[SquadState]
    objectives: List[Objective]
    casualties: Casualties
    ai_count: AICount
```

### Command schema (Pydantic)

```python
class CommandParams(BaseModel):
    formation: Optional[str] = None
    stance: Optional[str] = None
    combat_mode: Optional[str] = None
    completion_radius: Optional[float] = 15.0
    replace_existing: Optional[bool] = True

class Command(BaseModel):
    command_id: str
    squad_id: str
    action: str  # MOVE, ATTACK, DEFEND, HOLD, FORMATION, STANCE
    position: Optional[List[float]] = None  # None for HOLD/FORMATION/STANCE-only
    params: CommandParams = CommandParams()
```

## Error Handling

### Game-side (Enforce Script)

| Scenario | RestCallback method | Fallback action |
|---|---|---|
| Bridge returns 4xx/5xx | `OnError(errorCode)` | Log error, continue (vanilla AI) |
| Bridge doesn't respond | `OnTimeout()` | Log timeout, HOLD all groups |
| Bridge returns malformed JSON | `OnSuccess(data)` with parse failure | Log, skip command, continue |

### Bridge-side (Python)

| Scenario | HTTP response | Action |
|---|---|---|
| Malformed SITREP JSON | 422 Unprocessable Entity | Pydantic rejects, returns validation errors |
| LLM call fails | 503 Service Unavailable | Log, skip command generation |
| LLM returns invalid JSON | 502 Bad Gateway | Log, skip, do NOT queue invalid command |
| Internal error | 500 Internal Server Error | Log traceback, continue serving |

## Polling cadence

| Brain | Poll interval | Rationale |
|---|---|---|
| Tactical (BLUFOR poll) | 2 seconds | Fast enough for gameplay responsiveness |
| SITREP push | 5 seconds (normal) or immediate (on kill event) | Balance between accuracy and load |
| Strategic (Stavka trigger) | 60-120 seconds | Slow, deliberate; bridge calls LLM on this timer |
| Health check (`/status` or `/health`) | 10 seconds | Detect bridge restart quickly |

> Polling intervals are implemented via `GetGame().GetCallqueue().CallLater(method, delayMs, true)`
> in the game mod, and via `asyncio` tasks or timer middleware in the bridge.
